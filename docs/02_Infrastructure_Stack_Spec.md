## 1. Container Architecture (Docker Compose)

The Prisma V4 core runs on an orchestration of isolated services. This architecture ensures our IP (Intellectual Property) remains sovereign and independent of external clouds.

### `docker-compose.yml` Services:

#### A. `prisma-orchestrator` (The Brain)
- **Image:** Python 3.11 (Custom build).
- **Function:** Executes **LangGraph**. This is where the TRM Cognitive Agent and workflows live.
- **Dependencies:** `langgraph`, `langchain`, `pydantic`.
- **Connections:** Communicates with `embedding-service` and `rag-manager`.

#### B. `embedding-service` (Data Protection)
- **Image:** Ollama (or vLLM for production).
- **Loaded Model:** `google/gemma-2b` (or 7b depending on GPU).
- **Exposure:** Internal REST API (e.g., port 11434).
- **V4 Justification:** Ensures sensitive document vectorization (`/docs`) happens locally, without sending data to OpenAI/Anthropic.

#### C. `vector-db` (The Memory)
- **Image:** `ankane/pgvector` (PostgreSQL with pre-installed vector extension).
- **Function:** Stores embeddings from our knowledge base and agent execution logs.
- **Persistence:** Local Docker volume for data.

#### D. `rag-manager` (The Knowledge Interface)
- **Image:** FlowiseAI (`flowise`).
- **Function:** Visual interface to build, test, and maintain RAG pipelines.
- **Flow:** Flowise connects to `embedding-service` (to vectorize) and `vector-db` (to store). The `prisma-orchestrator` calls Flowise via API to obtain context.

## 2. Development Stack and Tools

### Code and Experiment Management
- **Branchlet:** Mandatory CLI tool to create isolated *worktrees*.
  - *Usage:* Every new feature or refactoring must be done in a separate `branchlet` to not pollute the stable core.

### Visual Prototyping
- **Google Stitch:** External tool used in the "Conception" phase.
  - *Flow:* Prompt → Stitch → HTML → `/src/prototypes/`.

## 3. Final Product Stack (What We Deliver to the Client)

Unlike internal infrastructure (Docker/Python), the final product generated by Prisma follows a **Serverless/Edge** architecture for client scalability.

| Layer | Technology | Notes |
|:---|:---|:---|
| Frontend | Next.js 15 (App Router) | Hosted on **Vercel** |
| Backend & DB | **Supabase** | Auth, PostgreSQL, RLS, Storage |
| Policy Agents | Supabase Edge Functions | Where V4 business logic resides |
| Client RAG | Google File Search API | RAG-as-a-Service (not local stack) |
| UI Components | Tremor + Magic UI + shadcn/ui | Premium MCP catalog |
| Validation | Zod | Input schema validation |

## 5. Dual-Mode (IDE Solo Mode)

### The "Antigravity IDE" Runtime
While the Docker stack is used for production deployment and multi-agent Python execution (LangGraph), Prisma AI V4.2 also operates as a **Solo Agent within an IDE** (e.g., Antigravity).

In IDE Mode:
- **No Docker:** The agent uses native IDE tools (`grep_search`, `write_to_file`, `run_command`).
- **Simulated Orchestration:** The agent simulates hat-switching (Architect -> Worker -> Auditor) internally.
- **Subagents (Antigravity 2.0):** The IDE's subagent spawning capability replaces LangGraph nodes for task delegation.

The architecture remains the same conceptually, but the transport layer changes from HTTP/Docker to IDE native tool calls.
